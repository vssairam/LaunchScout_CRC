1. The assignment

The brief (LaunchScout_CRC.md) asks for a team of AI agents that researches the market for a new business idea and delivers a competitor report with prices, gaps and a launch plan.

  • Four CrewAI agents in a sequential process: Market Researcher, Review Analyst, Strategy Analyst, Report Writer.
  • A Streamlit app with an input form (idea, city, target customer, optional known competitors), a live view of which agent is working, and Markdown / PDF download.
  • A six-section report with sourced claims, saved to report.md, working for any idea and city.
  • Stretch goals: a hierarchical Manager agent, a Pitch Deck agent (6 slides) and weekly re-runs that highlight price changes.
The main design decision. A language model will happily write a convincing price it never saw. A competitor report with invented prices is worse than no report. So the solution does not ask the model to find facts. It gives the agents a tool that returns real quotes from real pages, then re-checks each quote against the page and sends the agent back when it cannot be confirmed.

2. Solution at a glance

Everything runs through one function, run_crew() in crew.py. The web app and the command-line script both call it, so a scheduled weekly run behaves exactly like a click in the browser.

3. A run, step by step

What happens, in order, when someone presses Run research crew (or starts weekly_rerun.py).

1

The inputs are collected

The form holds the business idea, the city, the target customer and optional known competitors, plus three options: a pitch deck, the number of runs (1 to 3) and hierarchical mode. Because the inputs are just text, the same code serves any idea in any city. Missing required fields stop the run before any credits are spent.

2

The app starts the crew in a background thread

Streamlit reruns the whole page on every interaction and the crew takes minutes, so the crew runs in a worker thread. The agents' callbacks push short messages into a queue. The page loop reads the queue every half second, ticks the badge of the agent that just finished and repaints the last 25 log lines. That is how the page can show which agent is working right now.

3

A pre-flight check proves search works

check_search() sends one test query to Serper. An invalid key or an empty account would otherwise let the agents carry on without sources and invent data. That actually happened early in development, so the run now stops with a clear error instead.

4

Agent 1: the Market Researcher finds competitors and prices

It searches, scrapes pages and calls price_finder for every competitor. The tool fetches the competitor's page (or Google snippets of it when the page needs JavaScript) and returns lines such as EVIDENCE | Millet Express | https://… | "Millet Roti with Kadai Veg Curry … 279". The agent must copy one such line per price. Its output is a table: competitor, Direct or adjacent, location confirmed, price with unit, monthly plan, offers, channel, contact and source URL.

Guardrail 1 then checks the table (see section 5) and can send the agent back up to three times.

5

Agent 2: the Review Analyst finds what customers say

For each competitor it searches for third-party reviews (Google Maps, Zomato, Swiggy, Justdial, Reddit, blogs). Every like or complaint needs a short quote, the exact review URL, the review count and the rating, or the line No third-party reviews found. It is told never to infer a complaint.

6

Agent 3: the Strategy Analyst builds the plan

It has no tools on purpose, so it can only reason from what it was handed. It builds the comparison matrix, picks the one biggest market gap and proposes a positioning with a price. The price must be derived from the competitors' verified prices: list them, show the lowest, highest and median, and state the rule. Unverified prices are excluded and the reason given.

7

Agent 4: the Report Writer assembles the report

It writes the six sections, numbers the sources and adds a week-by-week 30-day launch plan. Guardrail 2 checks consistency, such as arithmetic, wording, and whether the cited sources are real. The writer can be sent back up to three times.

8

Optional: the Pitch Deck Designer makes 6 slides optional

A fifth agent turns the finished report into exactly six slides without adding facts or numbers (see section 9).

9

The program finishes the job itself

After the agents stop, run_crew() does the things that should not depend on a model's mood:

  • saves the report to output/report.md (it does not trust the agent's own file write);
  • refuses a report with fewer than 3 real source URLs rather than showing it as if it were sourced;
  • runs every check one last time and writes anything still wrong to report_warnings.txt;
  • saves a price snapshot and, when an earlier run exists, writes changes.md;
  • scores the run and copies all its files to output/runs/<idea>__<timestamp>/.
10

The app shows the result

The tabs are Report (with quality warnings and Markdown / PDF download), Changes since last run, Quality score and, when requested, Pitch deck (with a PowerPoint download). When the page is opened without running anything it shows the last saved run, so downloads work without spending credits.

5. Guardrails: the retry loop

A guardrail is a function CrewAI runs on an agent's answer. It returns "accept" or "reject, and here is what is wrong". A rejection becomes the next instruction the agent receives, so the agent corrects specific mistakes rather than starting again blind.

What the feedback looks like

Report rejected: page for a different city than Coimbatore: https://www.zomato.com/hyderabad/millet-express-kondapur/reviews;
section 2 complaint has no real source link ...; Return the COMPLETE corrected report Markdown.

Every message names the problem and the fix, because a model fixes "remove the Dharthi Foods row: it is priced per 250 g" far more reliably than "try again".

6. How a price gets verified

Every numeric price in the table must be backed by an EVIDENCE line: the competitor, the URL and a verbatim quote that contains the price. verify_research() then walks each price through the decisions below and assigns one status.

StatusMeaningWhat happens
verifiedQuote found word for word on the pageTagged [verified] in the report.
verified-approxMost quote words and the price figure are on the pageAccepted as verified.
verified-snippetPage unreadable; a search snippet shows the figure beside the same wordsTagged [verified via search snippet]; weaker evidence.
unverifiablePage unreadable and no snippet confirms itAllowed but tagged [unverifiable - confirm manually] and costs score.
mismatch / unsupportedThe page does not contain the price, or no evidence backs itBlocks the research; the agent must re-check or write Not found.
A repair step in code. Models often forget to add EVIDENCE lines. autofill_evidence() re-runs the same price tool in code for any priced competitor without one, and keeps a quote only if it contains the table's figure and belongs to that competitor.

7. The quality checks

All checks are small functions in verify.py. Each takes the report text and returns the offenders, so the same function serves the guardrail (to give feedback), the final warnings (to record what is left) and the score (to deduct points).

CheckCatchesWhy it matters
Location names the city"Yes, website" or a competitor in another cityA competitor you cannot reach in the target city is not a competitor.
No online shopsProduct pages, Amazon, Flipkart, /collections/Packaged goods are not meal-delivery businesses.
Price per meal, not per pack"₹140 per 250 g upma mix"A pack price cannot be compared with a meal price.
No "for two" or stale pricesDine-in costs for two; sources two or more years oldPrices must be comparable and current.
Direct is earnedA "Direct" competitor whose row never mentions the productStops loosely related businesses being labelled direct.
Missed subscriptionsEvidence mentions a monthly plan but the plan cell says "Not found"Keeps the "no one offers a subscription" claim honest.
Arithmetic"219.50 x 30 = 6,570" recomputedModels make arithmetic slips in price logic.
Uncheckable claims"first", "only", "growing demand"Nothing in the evidence can prove these.
Absence as fact"No competitor offers a subscription"Must read "none found in the sources reviewed".
Complaints have a real sourceNo link, a generic Instagram popular page, or a page for another cityAdded after a test run cited a Hyderabad outlet's reviews for a Coimbatore competitor.
Contact consistency"No contact found" for a row that has a phone or linkThe report must not contradict itself.

8. The quality score

Each run gets a score from 0 to 100 computed only from the automatic checks (no extra AI calls). It starts at 100 and loses points; the app lists every deduction so the number is never a black box. It is used to choose the best of several runs.

DeductionPoints
Each unresolved report problem the guardrails could not fix (first three; the rest together)−15
Each unresolved deck problem (first two)−10
Fewer than 3 competitor rows−20
Fewer than 2 Direct competitors−15
Fewer than 3 distinct source URLs−15
Fewer than 2 competitors with a numeric price−15
Each unverifiable price−5
A price under 40% of the highest (likely a side item)−10
A per-weight or per-pack price shown as a meal price−10
A platform summary sentence presented as a customer quote−10
Market gap that contradicts a Direct competitor in the table−20 (once)
What the score is not. It cannot tell whether a price on a page is the right price, or whether a review is about the right outlet. A score of 100 means the report passed the structural and consistency checks, not that it is true. A person should still check the prices before relying on them.

9. Stretch goals

9.1 Hierarchical Manager mode experimental

In the default sequential process the order is fixed. In hierarchical mode a Project Manager agent decides who does what and checks the work.

9.2 Pitch Deck agent

Ticking the checkbox adds a fifth agent that reads the finished report and writes exactly six slides: The opportunity, Who we compete with, What customers say, The market gap, Our positioning and price, 30-day launch plan. Its guardrail rejects a wrong slide count, more than 5 bullets on a slide, uncheckable claims, absence stated as fact and, importantly, any number that is not in the report. The deck is exported to deck.pptx. If the deck still has no slides (this happened once in hierarchical mode), it is rebuilt from the report by a single stand-alone designer agent.

9.3 Weekly re-runs with price tracking

Search results change from run to run, so a competitor appearing or disappearing is not always a market change. The changes file says so.

9.4 Best of N runs

The Runs setting (1 to 3) runs the whole crew several times, scores each run and keeps the best. Every run is archived under output/runs/ and best_of.md lists all scores. This exists because one run's quality varies with what the search returns.

10. The Streamlit app

  • Form. Pre-filled with the sample idea so it can be tried with one click. Widget values are only sent when the submit button is pressed.
  • Live status. One badge per agent shows waiting, working or finished, with the last 25 steps in a log underneath. A badge moves on when that agent's task callback fires.
  • Results survive reruns. Streamlit re-executes the script on every click, so the report, score and deck are kept in st.session_state. The PDF is built once per report, not once per click.
  • Warnings are visible. Problems the crew could not fix appear above the report so nobody shares it unaware.
  • Saved run on load. A fresh page shows the last saved run from output/, so downloads work without a paid run.
  • PDF note. The built-in PDF font has no rupee sign, so the PDF writes "Rs " instead of ₹.

12. Results and honest limits

The sample used throughout was "Healthy millet meal boxes delivered for lunch" in Coimbatore, for "Office workers, age 25 to 40".

What the test runs showed

RunCompetitorsScoreWhat went wrong or right
Early live runs2 to 4variedExposed invented data (invalid search key), a missing evidence step and a report overwritten by the agent's closing chat line. Each led to a fix.
Run with deck (kept as run 2)245Only two competitors; an uncheckable "Coimbatore's first" claim.
Fresh run with deck475Included a packaged-food product (priced per 250 g) as a competitor, and an unsourced Instagram complaint.
Fresh run after new checks250The only complaint cited an outlet in Hyderabad, not Coimbatore. Led to the wrong-city check.
Hand-edited version3100The 75 run with the packaged product and the unsourced complaint removed by hand.
Read this before relying on the sample. The kept report and deck are the hand-edited version, and the 100 comes from the automatic checks only. The report still states the missing subscription gap flatly in section 3, and "Price conflicts: None" is not independently checked. Mummy's Cloud Kitchen's ₹180 was confirmed on its own page; Millet Express's ₹279 comes from a search snippet.

Known limits

  • Search varies. Google returns different pages from run to run, so the competitor list and reviews change. Thinly covered local markets can end with fewer than 3 competitors; the report then says so.
  • The checks look at structure, not relevance. They cannot know whether a review is truly about the right outlet; a person should read the report before sharing it.
  • JavaScript sites cannot be read directly, so their prices rest on search snippets that may be out of date.
  • Cost. Each run uses Serper credits and OpenAI tokens; extra runs multiply that. During testing the Serper account ran out of credits, which stops new runs (the saved results stay available).
  • The last checks (wrong-city and unsourced-complaint) and the deck rebuild were tested on saved reports, not yet in a further live run.

14. How to run it

python -m venv .venv
.venv\Scripts\activate            # or call the programs directly (see below)
pip install -r requirements.txt
copy .env.example .env            # add SERPER_API_KEY, OPENAI_API_KEY, LLM_MODEL
.venv\Scripts\streamlit.exe run app.py

Open the address Streamlit prints (usually http://localhost:8501), fill in the form and press Run research crew.

For a scheduled weekly run:

.venv\Scripts\python.exe weekly_rerun.py --idea "Healthy millet meal boxes delivered for lunch" ^
    --city Coimbatore --customer "Office workers, age 25 to 40" --deck
If a run fails at once with "Web search (Serper) is not working", check the Serper account first. "Not enough credits" means the account is empty, and credits belong to the account, so a new key for the same account does not help.
